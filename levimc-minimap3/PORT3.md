## Почему в Минимапе 2 растёт ОЗУ и падает FPS (архитектурная разница с Java)
Java (render/MapLevel.java, MapMemory.java, data/TileStore.java):
- в ОЗУ хранится не весь мир: снимки чанков MAX_CHUNKS=4096, при превышении обрезка до 3/4;
- на GPU максимум MAX_GPU_TILES=256 плиток (512x512, ~1 МБ), держится 3/4, остальное выгружается;
- постоянным хранилищем служат ГОТОВЫЕ плитки на диске (TileStore), а не сырые данные колонок. Плитка грузится с диска в фоне, не пересчитывается;
- запекание плитки идёт на GPU (bake.vsh/bake.fsh, GpuMesher): процессор только готовит воксельные данные;
- туман считается шейдером (fog.fsh) по маске «известно/нет» из плиток (KNOWN_EDGE = 128 клеток на плитку).
Минимапа 2: сырые регионы (до ~27 МБ каждый) + пиксельные кэши + CPU-растеризатор высотной карты + CPU-маска тумана.

## Этапы
1. Хранение и память как в Java: плитка 128x128 блоков = 512x512 px, LOD, TileStore (диск), LRU на GPU-текстуры (256), снимки чанков <=4096, маска известного 128x128 на плитку.
2. Снимок чанка (data/ChunkSnapshot, bake/VoxelReader): воксельная палитра по секциям вместо профиля стен.
3. Запекание: порт bake/TileBaker.java (CPU-эталон), затем GPU-путь по bake.fsh/bake.glsl (переписать в HLSL, D3D12 хук уже есть в GpuHook.cpp).
4. Туман: fog.fsh -> HLSL. 5. Ночной режим tile_night. 6. Рамки, иконки вейпоинтов (ресурсы MIT есть в assets/diorama). 7. Большая карта, метки, рисование (DrawingStore).
