## 1. Склейка = dynamic property на блок
`world.setDynamicProperty("create_physics:glue_<dim>_<x>_<y>_<z>", true)`, где координата `pN`/`nN` (знак), dim — id измерения с заменой не-`[a-z0-9_]` на `_` (`physicsGluePropertyId`). Склеен ли блок: `isPhysicsGlued` = оболочка воздушного шара (`isHotAirEnvelope`) ИЛИ свойство `true` (`isPhysicsGlueExplicitlyApplied`). `togglePhysicsGlue` переключает одну клетку. При разборке свойства стираются (L20229).

## 2. Предмет «клей» и выделение области
- Предмет `create_physics:physics_glue`, custom component `create_physics:physics_glue_use` (`registerPhysicsGlueItem`): `onUseOn` → `services.useGlue(player, block, face)`; игнорирует блок-контроллер. В main.js `useGlue: handlePhysicsGlueAreaUse` (L120–156, четыре регистрации). Износ: `damagePhysicsGlue` — −1 прочности за применение, предмет исчезает на последней единице; в креативе без износа.
- `handlePhysicsGlueAreaUse(player, block, face)` — машина состояний на игрока (`physicsGlueSelections`):
  1. Дебаунс 4 тика. Если выделения нет / завершено / старше 600 тиков (`PHYSICS_GLUE_SELECTION_TIMEOUT_TICKS`) / другое измерение / сменился режим «убрать» (приседание = `remove`) → **начало**: спавн сущности `create_physics:glue_selection` в центре блока, запись угла, сообщение `action.create_physics.physics_glue.selection_start|remove_start`, звук.
  2. Иначе **конец**: `createPhysicsGlueArea(start,end)` — прямоугольный параллелепипед; объём > `PHYSICS_GLUE_MAX_SCAN_VOLUME = 32768` → «too_large» (подставляется `getContraptionBlockLimit()`), выделение сбрасывается. Из области берутся клетки, не воздух, не жидкость, не `create_physics:controller`; их число > `getContraptionBlockLimit()` → то же сообщение.
  3. Каждой клетке ставится/снимается свойство. `changed` считает только реально изменившиеся. Новые склеенные: частицы `create:spout_honey_fall` на открытых гранях, пачками по 12 клеток в тик.
  4. «Склеить»: `selection.end/finalized/locations`, `mergePhysicsGlueArea` (область объединяется со всеми касающимися финализированными: пересечение или смежность по грани, `doPhysicsGlueAreasTouch`; `location/end` = min/max по клеткам), область остаётся в `physicsGlueAreas` (подсветка). «Убрать»: визуал и выделение удаляются.
  5. Сообщения `area_applied|area_removed` со счётчиком, звук `mob.slime.squish` / `random.pop`.
- `handlePhysicsGlueAirUse`: клик «в воздух» при незавершённом выделении (не режим «убрать») берёт точку в 8 блоках по взгляду как конец области.
- Предпросмотр (`updatePhysicsGlueSelectionVisuals`, периодически): пока выделение не финализировано, игрок должен держать клей в основной руке, иначе выделение снимается; рамка (`scale_x/y/z` ≤128, `confirmed`) тянется к блоку под прицелом или к точке в воздухе. `updatePhysicsGlueHoneyFaces` каждые ≥6 тиков (на тач-устройствах ≥10) рисует сетку частиц `create_physics:honey_selection_xy|xz|yz` на всех гранях в радиусе 32 от зрителей — это самое «дорогое» место UI. `updatePhysicsGlueAreaHighlights`: ближайшая под прицелом (≤8) финализированная область получает `create_physics:highlighted=true`.
- Согласование с миром: `invalidatePhysicsGlueAreaAt` (сброс области со снятием клея), `removePhysicsGlueLocationFromAreas` (убрать сломанную клетку, пересчитать границы), `consumePhysicsGlueAreas` (области, чьи клетки вошли в конструкцию, забываются; клей не стирается), `findConnectedPhysicsGlueAreas`. Области в `physicsGlueAreas` живут **только в памяти скрипта**; сама склейка (свойства) — в мире. После перезапуска подсветки областей нет, склейка остаётся.

## 3. Фильтр ландшафта (`glue_filter.js`, RZ Lite)
`isTerrainBlock(typeId)`: только `minecraft:*` и имя входит в `TERRAIN_EXACT` (земля, песок, природный камень, снег/лёд, растения, скалк, паутина, огонь и др.) или в регулярки (`_ore$`, `_leaves$`, `_sapling$`, `_coral`, `_fungus$`, `_roots$`, цветы…). Блоки других пространств имён (аддон) — всегда можно. В main.js используется как `rzIsTerrain` (сообщение «Ландшафт … не склеивается» при сборке, L20036). `CORE_ID = "phys:core"` экспортируется отсюда же и в main.js импортируется как `RZ_CORE_ID` (main.js L47: `import { isTerrainBlock as rzIsTerrain, CORE_ID as RZ_CORE_ID } from "./blocks/glue_filter.js"`), то есть **ядро конструкции = блок `phys:core`**. (Первая версия документа ошибочно утверждала, что это разные ID: исправлено после проверки импорта.) Замечание: камень `cobblestone`, `stone_bricks`, кирпич и пр. в списке НЕТ — их склеивать можно.

## 4. Поручень-груз (`handrail_cargo.js`)
Поручень (`create_physics:handrail`) — рельса со «слайдером» `create_physics:handrail_panel`; панель тянет за собой блоки над собой (груз). Состояние `entry.state = {origin, axis, offset, cargo?, guided?, ...}` хранится в dynamic property сущности `create_physics:handrail_motion` (JSON; лимит ≈26000 символов — иначе «слишком много данных»).
- `captureCargo(entry)`: семя = клетка над панелью со смещением `offset`; состав груза — **родная склейка** (`collectBlocks` → `collectPhysicsGlueStructure(source, true)` без самого поручня и панели), а не заливка соседей. Запрещено: жидкости, bedrock/barrier/portal/structure_block/command_block, поручень и панель. Для каждого блока: `{dx,dy,dz,typeId,states,structure}`. Каждый блок **сохраняется в структуру** `StructureManager` (`create_physics:handrail_<id>_<ts>_<i>`, `includeBlocks`, без сущностей, `World`) — чтобы пережили инвентари/таблички. Порядок: сохранить структуры → создать сборку (валидирует рендер ДО удаления) → заменить исходные блоки воздухом → фаза `moving`. При ошибке — откат: поставить структуры обратно, удалить сборку.
- Фазы груза: `capturing` → `moving` → `restored`. Пустой груз (только панель) тоже получает физическое тело (слайдер всегда с ограниченным телом).
- `handrailAssemblyOptions(axis)` (main.js L24772): тело `dynamic`, `allowSleep:false`, `linearFactor` разрешает только ось рельсы, `angularFactor` 0, базовый блок `handrail_panel` (масса 2, `render:false`, `collisionResponse:false`, коллайдер верхняя четверть клетки).
- `createAssembly` (main.js L24800): ключ сессии `handrail|<dim>|<entityId>`; сессия с `handrailEntry`; телепорт тела в позу `anchor + offset`; инвентари — через тот же `capturePhysicsStorageEntities` (с подменой исходных координат на `offset`), повторно только для блоков без `storageEntityId`; `configureHandrailControllerEntities` (сундуки, vault, заборы, винты, handles, горелки, кресла, коллизии); затем `splitDisconnectedPhysicsControllerSession`, если груз «моего поручня» оказался несвязным.
- `settleCargo(entry)`: ставит структуры обратно в мир в клетки назначения (`offset` или `sourceOffset` при откате); НИКОГДА не заменяет чужие блоки: если клетка занята (кроме отката) — вернёт `false` и ждёт. После — `disposeSession`, удаление сборки/визуалов, удаление структур.
- `releaseCargoFromBrokenPanel`: при поломке панели/рельсы груз остаётся физическим (`releaseSession`), структуры стираются, `state.guided=false` (восстановление в мир могло бы упереться в препятствие и оставить панель-сироту).
- `removeStaleCargoVisual(entity)`: визуал с тегом `handrail_cargo_<parentId>`, которого нет в `visualIds` родителя — удаляется.
- Синхронизация: `syncHandrailControllerSession` переписывает `cargo.blocks` из снапшотов сессии (после слома/склейки), обновляет `visualIds`, чистит структуры убранных блоков.

## 5. Для переписывания
(1) Склейка — булев флаг на блок в мире + рантайм-области только для подсветки; (2) область ≤32768 клеток и ≤ лимита блоков; (3) сначала сохранить, потом проверить рендер, потом удалять блоки мира — всегда с откатом; (4) никогда не заменять чужие блоки при возврате груза.

`getBlockHardness(block) = BLOCK_HARDNESS[block.typeId] ?? 3` — чистая таблица из 1110 записей (только `minecraft:*`, ни одного `create:*`; в конце мусорная запись `undefined: 0`).
